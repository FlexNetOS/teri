## Layer 10 — Runtime / Concurrency / Signal Contracts (first-class rows)

- [ ] U-045 · RUNTIME: Background thread management · Three categories of daemon threads: (1) task threads (`build_graph_async`, `prepare_simulation`, `generate_report`) — one per operation, captures locale before spawn, reports progress via TaskManager or file; (2) monitor threads (`_monitor_simulation`) — one per active simulation, polls JSONL file by offset every 2s, writes to `ZepGraphMemoryUpdater` queue; (3) Zep memory worker thread — one per simulation with graph memory enabled, processes queue in BATCH_SIZE=5 groups. All daemon=True. Contract: no join on cleanup; signal handlers call `cleanup_all_simulations()` which terminates subprocesses. Parity risk: sequential polling → must not become blocking in Rust; daemon thread semantics must be preserved. → `teri::runtime::thread_manager` · deps: U-022, U-021

- [ ] U-046 · RUNTIME: Subprocess lifecycle · `SimulationRunner.start_simulation` spawns `python run_{platform}_simulation.py --config {path}` as `subprocess.Popen`; stdout redirected to `{sim_dir}/stdout.log`; process group created via `os.setsid()` (Unix) for group kill; `_terminate_process` sends SIGTERM to process group, then SIGKILL after 5s if still alive; Windows: `taskkill /F /IM /T`; subprocess inherits env (LLM_API_KEY etc. must be in env). Contract: exactly one subprocess per simulation_id; monitor thread starts after subprocess. Parity risk: Rust port must replicate pgid-based kill, graceful shutdown window. → `teri::runtime::subprocess_lifecycle` · deps: U-022

- [ ] U-047 · RUNTIME: File-based IPC protocol · Flask ↔ simulation subprocess communicate via `{sim_dir}/ipc_commands/` and `{sim_dir}/ipc_responses/` directories; `{command_id}.json` files; client polls response dir every 0.5s; command file deleted on response; `env_status.json` for liveness check; timeout raises `TimeoutError`. Contract: single producer/consumer per command; interview timeout=60s default (batch=120s). Parity risk: file polling must be async-safe in Rust. → `teri::runtime::ipc_protocol` · deps: U-020

- [ ] U-048 · RUNTIME: JSONL action log streaming · Action logs written by simulation subprocess to `{sim_dir}/{platform}/actions.jsonl` in real-time; Flask monitor thread reads by file position (seek + readline), parses each line; format: `{"round":N, "timestamp":..., "agent_id":N, "agent_name":..., "action_type":..., "action_args":{...}, ...}` for actions; `{"event_type":"round_end"/"simulation_end", ...}` for events. Enriched `action_args` in parallel script includes post/comment content. Contract: monitor thread never re-reads already-processed lines; file position tracked in `_run_states`. Parity risk: tail-like streaming must preserve ordering; no line lost on rotation. → `teri::runtime::action_log_streaming` · deps: U-022

- [ ] U-049 · RUNTIME: Signal/graceful shutdown · `register_cleanup()` installs handlers for SIGTERM, SIGINT, SIGHUP on the Flask process; all call `cleanup_all_simulations()` (terminates all subprocesses + Zep updaters); `atexit` registered as backup; `ZepGraphMemoryManager.stop_all()` called with `_stop_all_done` idempotency flag. Contract: handlers are process-level; safe to call multiple times. → `teri::runtime::signal_handling` · deps: U-022, U-021

- [ ] U-050 · RUNTIME: Locale propagation into threads · Flask's `Accept-Language` header sets thread-local locale; before any `threading.Thread` spawn, caller captures `current_locale = get_locale()` and passes it as arg; worker calls `set_locale(locale)` before any `t()` calls. Affected: `build_graph_async`, `prepare_simulation`, `generate_report`, `ZepGraphMemoryUpdater.start()`. Contract: `t()` in background threads must use worker-set locale, not Flask request context. Parity risk: Rust must replicate locale threading (task-local storage). → `teri::runtime::locale_threading` · deps: U-005
