# ADR-0004.1 — Single fail-closed inference-backend honesty guard, wired into `run` + `serve`

**Status:** accepted (2026-06-22) · **Owner:** teri engine · **Scope:** teri (`src/preflight.rs`,
`src/main.rs`, `src/lib.rs`) · **Supersedes:** the dual-guard state on `main` ≤ `823cca6`
**Numbering:** owner-assigned `0004.1`. This is teri's first local ADR; it carries a point number
because it amends the backend-guard discipline teri's `CLAUDE.md` referenced alongside meta
[ADR-0004](../../../handoff/docs/adr-0004-fleet-handoff-rollout.md) (fleet `.handoff` continuity).
It is **engine-scoped** — it does not change the handoff/continuity policy of meta ADR-0004.
**Derived from:** a `/verify` runtime drive of the `teri` binary (2026-06-21) that observed the
guard's wired behavior diverge from every doc describing it; PRs #13–#15.

## Context

A swarm pointed at a stub/canned inference backend (e.g. shimmy's SafeTensors engine, which
returns the fixed string "Full transformer inference coming soon!") fabricates an entire
simulation from canned text **with no error anywhere** — predictions indistinguishable from
garbage. teri's contract is therefore to refuse stub backends *before* any simulation work.

A `/verify` drive of the binary found the guard did **not** match its documentation. teri had
**two** guard implementations and the wrong one was wired:

| Implementation | Behavior | Wired? |
|---|---|---|
| `preflight::verify_backend` (strong) | `GET /models` → refuse unreachable / empty list → 1-token `/chat/completions` honesty probe → refuse canned text | ❌ dead code — only its own tests called it |
| `lib.rs::preflight_check_backend` (weak) | `GET /health` → scan body for stub phrases; sentinel completion only on a *connection* error | ✅ `run` only |
| *(none)* | — | `teri serve` had **no** guard |

Two latent failures followed, both runtime-confirmed:
1. **`teri run` silently accepted an unreachable backend** — the weak guard's sentinel returned
   `Ok(false)` ("not stub, proceed") on a connection error, so a dead/misconfigured endpoint
   sailed through. The guard caught *canned text*, never *absence*.
2. **`teri serve` booted against a stub backend** — it preflighted nothing; the API handlers drive
   the LLM, so the whole server would fabricate output once the pipeline lands.

The strong guard that already handled both cases correctly (refusing unreachable, empty, and
canned) was never called. teri's `CLAUDE.md`, `README.md`, and the (then-new) `RUNBOOK.md` all
described the *strong* guard's behavior — accurate as intent, false as wired.

## Decision

1. **One guard, single source of truth.** `preflight::verify_backend` is the only backend honesty
   guard. The weak duplicate (`preflight_check_backend`, `detect_stub_response`,
   `sentinel_completion`, `STUB_PATTERNS`) is **deleted** from `lib.rs`.
2. **Wired into BOTH commands, fail-closed**, via one shared `main.rs::preflight_backend` helper:
   `run` calls it before the pipeline; `serve` calls it **before binding the socket** — so
   `teri serve` refuses to *boot* against a stub/unreachable backend. There is **no bypass flag**:
   weakening the guard to make a run proceed is prohibited (a fabricated simulation is worse than a
   clear refusal).
3. **No detection downgrade.** The weak guard's broader stub phrases are folded into
   `preflight::STUB_MARKERS` so coverage is not narrowed by the deletion. A real spelling bug is
   fixed along the way: the old `"safe tensors"` (with a space) never matched shimmy's
   `"SafeTensors"`; the marker is now `"safetensors"`. Markers are matched case-insensitively and
   only against the 1-token probe reply — they can only trip an engine that *ignores* `max_tokens`
   and returns a fixed placeholder, so false positives on a real backend are structurally
   impossible.
4. **Refusal taxonomy** (all exit 1, before any work): backend down/wrong URL →
   `inference backend unreachable at …/models: …`; reachable but empty →
   `backend at … lists no models`; canned probe →
   `REFUSING stub inference backend at …: … (matched "<marker>")`.
5. **Docs track the wired reality.** `CLAUDE.md` (both guard sections), `README.md`, and
   `RUNBOOK.md` §6 are corrected to describe the single wired guard; `RUNBOOK.md`'s prior
   "intent-vs-wired" gap note is retired (resolved). The truth is the code path, and the docs now
   match it.

## Consequences

- A misconfigured or down backend now **fails loudly at startup** for both `run` and `serve`
  instead of silently proceeding (run) or serving a fabricating backend (serve). This is a
  behavior change for `serve`: it will not boot until its backend is reachable and real — the
  correct default, since the API is useless (and dangerous) without a real backend.
- `lib.rs`'s public surface shrinks by one `pub async fn` (`preflight_check_backend`); only
  `main.rs` referenced it, so the blast radius was internal.
- Detection is strictly broader than before (more markers + the `safetensors` fix), never
  narrower — consistent with the no-downgrade directive.
- Witnessed `.handoff/loop/*` analysis snapshots that reference the old `preflight_check_backend`
  symbol are left intact as timestamped records of the pre-upgrade state; this ADR is the forward
  record of the change.

## Verification

Runtime-driven against a mock OpenAI backend (stub/real modes) + a dead port, plus unit tests:

| Scenario | Result |
|---|---|
| `run` vs stub | `REFUSING stub inference backend … (matched "full transformer inference coming soon")` exit 1 |
| `run` vs real | guard passes → `Pipeline not yet implemented` exit 1 |
| `run` vs **dead port** | `inference backend unreachable …` exit 1 — was silent-proceed |
| `serve` vs **stub** | refuses to **boot**, exit 1 — was booting |
| `serve` vs real | boots, `/health` 200, `/api/*` 200 — regression-safe |

Tests: +7 in `preflight.rs` (5 `httpmock` `verify_backend`: pass / empty-models / canned-probe /
non-2xx / unreachable; 2 marker: `safetensors`-no-space, generic stub signatures). Full suite
**1614 passed, 0 failed**; `cargo fmt --all --check`, `cargo clippy --all-targets -- -D warnings`
clean; CI green (Format, Clippy, Test default + all-features, Build, cargo-deny).
